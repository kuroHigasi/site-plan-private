# P010-01: ブログ記事 (/blog/article?slug=sample-article-1)

## 基本情報
- 主目的: ブログ記事の詳細情報を提供し、情報発信やポートフォリオの補完を行う。
- 想定ユーザー: ポートフォリオ閲覧者、採用担当者、情報収集を行うユーザー。
- 想定導線:
  - 主: ブログ（P010）の記事一覧カードから遷移する。
  - 副: SNS や外部サイトから本ページへ直接遷移する。

## ルーティング・実装方式

本ページは管理画面から記事を追加するだけで再ビルド不要で公開できるよう、**単一の静的ページ + クライアントサイド取得**で構成する。

| 項目 | 方針 |
|------|------|
| URL 形式 | `/blog/article?slug={slug}`（クエリパラメータで記事を指定） |
| ページ生成 | `blog/article.astro` を 1 ファイルだけ静的生成する。`slug` 別の `getStaticPaths` は使用しない |
| データ取得 | ブラウザで `slug` を `URLSearchParams` から取得し、`GET /api/public/blog-articles.php?slug={slug}` を呼び出して描画する |
| Markdown 変換 | API レスポンスの `content`（Markdown テキスト）をクライアント側の `marked` ライブラリで HTML へ変換し、対象 DOM 要素に `.innerHTML` で描画する |
| スタイル補正 | `@tailwindcss/typography` の `prose` クラスを使用し、変換後の見出し・リスト・コードブロック等のスタイルを自動補正する |
| 記事追加運用 | 管理画面で記事を公開すれば、再ビルド・再デプロイなしで詳細ページが閲覧可能になる |
| slug 不正・未指定 | API の `slug` 制約（`^[a-z0-9]+(?:-[a-z0-9]+)*$`）に準拠して検証し、不正・未指定時はエラー表示 + 一覧へ戻る導線を出す |
| slug 不存在・非公開 | API が `404` を返すため「記事が見つかりません」を表示し、一覧へ戻る導線を出す |

> SEO トレードオフ: クライアントサイド JS で描画するため、検索エンジン（Google bot 等）へのインデックス登録（SEO 効果）は弱くなる。本ページは頻繁に更新されるブログ記事の表示を目的としており、管理画面からの即時公開（再ビルド不要）を優先して許容する。OGP・`title` は API レスポンス取得後にクライアントで更新する（下記「SEO・アクセシビリティ」参照）。sitemap はビルド時に一覧 API から `slug` を取得し `?slug=` 付き URL を列挙する（詳細 HTML の再生成は不要）。

## 識別情報（管理画面連携）

| 項目 | 詳細 | 備考 |
|------|------|------|
| slug | URL 用識別子（例: `sample-article-1`） | 英小文字・数字・ハイフンのみ。一覧・詳細で共通 |
| category | カテゴリ（例: `frontend`） | P002 プロフィールで表示するカテゴリと等しい |
| skills | スキルタグ（例: `["HTML", "CSS"]`） | P002-01〜P002-04 で表示するスキルと等しい |
| published_at | 公開日 | P010 一覧の表示日と同一ソース |
| is_published | 公開 / 下書き | 下書き時は一覧・詳細とも非表示 |

## 表示内容

| 要素名 | 詳細 | 備考 |
|--------|------|------|
| タイトル | ページ見出し（H1）として表示 | パンくず・OGP タイトルに使用。P010 一覧のタイトルと同一 |
| カテゴリ・スキル表示 | カテゴリ名とスキルタグを表示 | P010 一覧のカテゴリ・スキルと同一ソース |
| 公開日 | 記事の公開日を表示 | `published_at` を `YYYY年M月D日` 形式等で表示 |
| サムネイル | 記事のサムネイル画像を表示 | 一覧カードと同一画像を使用。`alt` はタイトルを設定 |
| 本文 | Markdown 形式の本文を HTML 変換して表示 | `marked` で変換後、`prose` クラス適用の要素に描画 |
| 関連記事表示 | 関連するブログ記事のリンクを表示 | 同一カテゴリまたは同一スキルの記事。0 件の場合はセクションごと非表示 |
| 一覧へ戻る | P010 へのリンクを表示 | `画面遷移図.md` 備考に準拠 |

## クライアントサイド処理フロー

```text
[ユーザー] -> (ページ閲覧)
  └─> [Astro(静的HTML)] 描画完了（Loading 状態を表示）
        └─> [クライアントJS] 発火
              ├─> 1. URLSearchParams から slug を取得・検証
              ├─> 2. GET /api/public/blog-articles.php?slug={slug} へリクエスト送信
              ├─> 3. レスポンス（JSON）から記事データを抽出
              ├─> 4. content（Markdown）を marked ライブラリで HTML へ変換
              ├─> 5. DOMPurify でサニタイズ
              └─> 6. 対象の DOM 要素（prose クラス付き）に .innerHTML で描画（Success 状態）
```

### 画面上の状態（State）定義

| 状態 | 表示内容 | 遷移条件 |
|------|----------|----------|
| Loading | スケルトン UI またはスピナーを表示 | ページ描画完了〜API レスポンス受信まで |
| Success | 変換後の HTML（タイトル・本文・関連記事等）を描画 | API が正常レスポンス（200）を返却 |
| Error | 「データの取得に失敗しました」等のフォールバック表示 + 一覧へ戻る導線 | API エラー（404・500 等）、ネットワークエラー、slug 不正 |

## セキュリティ

### XSS（クロスサイトスクリプティング）対策

API から返却される Markdown テキスト内に悪意ある HTML/JavaScript タグ（`<script>` 等）が注入されている場合、`.innerHTML` 描画時に実行されるリスクがある。

| 対策箇所 | 対策内容 |
|----------|----------|
| 管理画面（PHP 側） | 投稿・編集時に入力チェックを行う |
| フロントエンド | `marked` で HTML 変換後、`DOMPurify` を通過させてからDOMに描画する |

## SEO・アクセシビリティ

- OGP: タイトル・概要の抜粋・サムネイル画像を設定する（`05_SEOとアクセシビリティ方針.md` 参照）。クエリパラメータ構成のため、API レスポンス取得後にクライアントで `document.title` と `og:*` メタを更新する。
- canonical: `?slug=` 付きの自ページ URL を canonical とする。
- 構造化データ: `Article` の実装を検討する。クライアントで JSON-LD を注入する。
- サムネイル: `<img>` に `alt` を必須とし、`loading="lazy"` を付与する。
- 本文描画領域: `prose` クラスを適用し、見出し・リスト・コードブロック等のアクセシビリティを確保する。
- パンくず: `共通仕様.md` 2.4 に P010-01 定義を追加する（`トップ / ブログ / [記事名]`）。
